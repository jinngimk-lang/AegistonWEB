研发是企业里**流程最完整、可验证性最强**的场景——也是 AI 断点最密集的场景。

## 研发链路的断点：上下文在每一次交接处丢失

需求 →（断点）→ 规划 → 开发 →（断点）→ 测试 →（断点）→ 修复 → 验收

- 每一次交接都要重新讲一遍背景，上下文在环节之间反复丢失。
- AI 只能覆盖单点（写一段代码、答一个问题），无法跨环节接力。
- 链路越长，人工搬运与二次确认的成本越吃掉效率增益。

## 01 Agent 会写代码，却进不了流程

| 缺什么 | 具体表现 |
| --- | --- |
| 无归属人 | 产出不知道该算谁的工作量、由谁负责 |
| 无评审 | 没有走团队既有的评审与验收路径 |
| 无版本 | 变更没有进入版本与迭代计划 |
| 无审计 | 改了什么、为什么改，事后查不到 |

结果：Agent 的产出只能靠人工搬运回研发系统，**效率增益在交接处被吃掉**。

## 02 交付现场的三重现实约束

**无外网** —— 政企、军工、能源等交付现场普遍不允许连接公网，公有云 Agent 直接不可用。

**无算力** —— 现场没有 GPU 服务器，也来不及新建机房或申请算力资源。

**临时队** —— 项目制作业，队伍临时组建、随项目解散，环境必须即开即用。

因此需要：**开箱即用的本地算力 + 协作平台**，而不是又一个云端订阅。

## 03 为什么先在研发里跑通

- **流程最完整**：需求、评审、版本、缺陷、验收环节齐备，能真实检验治理能力。
- **结果可验证**：代码能否编译、测试是否通过、缺陷是否复现，都是硬指标，不靠主观判断。
- **回归最频繁**：改了再测、测了再改，天然是环状流程，最能压测调度与重入机制。
- **可复制性强**：跑通的身份、权限、流程与审计机制，可直接迁移到合同审核、方案评审等业务场景。

## 结论

在研发里跑通人机协同，才能把同一套机制复制到其他部门和业务场景。
